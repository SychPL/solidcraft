# Spike t2 - PR-y i probe przez gh api

Data: 2026-10-26, wątek w chmurze na SychPL/solidcraft. Nic nie zostało utworzone.

## Środowisko
- gh 2.89.0; `gh auth status`: token w GH_TOKEN nieważny - ruch idzie przez proxy agenta, które samo dokłada poświadczenia tylko dla repo podpiętych do sesji (SychPL/solidcraft, SychPL/solidcore).

## 1. Otwarte PR-y autora SychPL w tangency-labs/solidcraft i tangency-labs/solidcore
Nie udało się pobrać. Oba wywołania
`gh api "repos/tangency-labs/<repo>/pulls?state=open&per_page=100"`
zwróciły:

    HTTP/1.1 403 Forbidden
    {"message":"GitHub access to this repository is not enabled for this session. Use add_repo to request access. ..."}

Próba podpięcia (`add_repo`, access=push) odrzucona dla obu repo:
"a different repository named "solidcraft" (sychpl/solidcraft) is already attached to this session ... Same-named repositories from different owners can't share a session" (to samo dla solidcore).
`add_repo` read: dostępny tylko anonimowy git clone/fetch, bez REST API.

Wniosek: z sesji, która ma fork o tej samej nazwie, nie da się odpytać API upstreamu.
Trzeba osobnej sesji ze źródłem tangency-labs/* (bez forków o tej samej nazwie).
Stanu checków w związku z tym brak.

## 2. Probe POST (wykonany raz)
Sprawdzone wcześniej: gałąź `spike-does-not-exist` nie istnieje w SychPL/solidcraft (`git ls-remote` pusty).

    gh api -X POST repos/tangency-labs/solidcraft/pulls -f title=probe -f head=SychPL:spike-does-not-exist -f base=main

Wynik: **HTTP 403 Forbidden** (od proxy sesji, żądanie nie dotarło do GitHuba):

    {"message":"GitHub access to this repository is not enabled for this session. Use add_repo to request access. ..."}

Spodziewane 422 "Validation Failed" od GitHuba nie wystąpiło, bo proxy blokuje repo spoza sesji już na wejściu. PR nie powstał.
